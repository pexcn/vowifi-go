# Vodafone UK 原版日志对照

2026-10-19，用户提供同一 Vodafone UK（234/15）、同一 GB SOCKS5 代理下原版成功连接的日志。以下仅记录协议元数据，不保存日志中的 SIM 身份、号码或认证材料。这是用户提供的运行证据，不是新 REA Evidence，也不表示本轮在运营商网络验证了重写代码。

原版实际连接的 ePDG 是 `148.252.188.96:500`，随后切换到 UDP 4500；此前重写版仅尝试了 `88.82.11.208`、`88.82.11.221` 的两个端口，均无回包。原版收到要求 DH group 2 的通知，最终选择 AES-CBC-128、HMAC-SHA1-96、PRF-HMAC-SHA1、MODP_1024，完成 EAP-AKA、最终 responder AUTH、Child SA，并取得 IMS REGISTER 200 OK。这证明该次原版连接没有被订阅状态阻止；不能用它证明其他时刻或其他业务可用。

重写版之前只提出首个受支持的 IKE/ESP 配对，DH 固定为 14，因此缺少原版实际使用的算法组合。本次实现：

- 保留配置中支持的多组 IKE 提议，并严格核对服务器所选提议的编号和全部 transforms。
- 默认仍为 DH14；只有配置明确提出的 DH2 才能参与协商。收到合法 `INVALID_KE_PAYLOAD` 后，最多重新发起一次 KE 交换，重新生成 SPI、DH 私钥和 nonce，拒绝未提出的组或重复切换。
- DH2 和 DH14 均验证 peer public value 范围及素数阶子群，并固定长度编码共享秘密。IKE/ESP 算法仍须满足引擎已有的配对限制。
- 透传已有的 `dns_server`，并先尝试其他解析地址的原端口，再尝试备用端口，最多八个地址/端口组合。没有将用户日志中的 ePDG IP 写死在运行配置中。

局部静态指令核对表明，原版 `ResolveUDPAddrAll`（`0xfa7d60`）支持在参数非空时创建指定 DNS 服务器的 Go Resolver，其 Dial 闭包位于 `0xfa8860`。原版和重写版地址解析结果不同的具体原因仍未得到证实；不能凭 IP 差异直接断定 DNS 被污染或某地址已失效。

按用户要求，本轮仅整理格式和检查代码差异，没有运行测试、竞态检查或等待 CI。需要用户重建后进行实网验证。
